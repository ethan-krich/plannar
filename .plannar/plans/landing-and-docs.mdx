## 2. Where It Lives

A single Next.js app at <code>apps/site</code>. Landing at `/`, docs under `/docs/*`. One deploy, one nav, shared theme tokens from `@plannar/core`.

**Stack:** Next.js 15 (App Router), `fumadocs-core`, `fumadocs-ui`, `fumadocs-mdx`, Tailwind v4 (project standard), `@plannar/core` for live Playground embeds inside docs.

### 4a. "Why Plannar" comparison table

Render this as an actual `<table>` on the landing (styled, not the raw `mdx-content` table). Three columns: **Plain markdown**, **Raw HTML** (the Karpathy-style "just have the model write a webpage" idea), and **Plannar**.

| Property            | Plain markdown       | Raw HTML page                   | **Plannar**                           |
| ------------------- | -------------------- | ------------------------------- | ------------------------------------- |
| Skimmable layout    | Walls of text        | Yes                             | **Yes** (tabs / cards / accordion)    |
| Interactive preview | No                   | Yes, but hand-rolled            | **Yes, via `<Playground>`**           |
| Token cost to write | Cheap                | Expensive (full page each time) | **Cheap** (MDX + reusable components) |
| Edit-by-the-user    | Easy (it's text)     | Hard (one giant blob)           | **Easy** (MDX with named imports)     |
| Agent re-runs       | Has to rewrite prose | Has to rewrite the page         | **Patches MDX in place**              |
| Looks like a doc    | Yes                  | Looks like a one-off webpage    | **Yes** (Fumadocs-style chrome)       |

This frames the pitch as a comparison, not a complaint. The user explicitly liked the "interactive HTML" idea but flagged it as token-expensive and brittle — that's exactly what this row argues.

## 6. Live Playground in Docs — The Key Trick

Compose `remarkStateBind` into Fumadocs's MDX pipeline. `fumadocs-mdx` accepts `remarkPlugins`; add ours, expose `<Playground>` in the global MDX components map, and every docs page can include live previews — same authoring experience as a plan.

**Effort:** small. **Win:** huge — the docs _are_ the demo. A reader scrolling through "State binding" sees a real Slider driving a real preview on the same page.

### Concrete wiring

- `apps/site/source.config.ts` — pass `remarkPlugins: [remarkStateBind({ bindings: shadcnBindings })]` to `defineConfig`.
