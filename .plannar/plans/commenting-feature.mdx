# Inline Commenting for Plans

Allow users to leave comments anchored to specific positions in a plan document. The editor collects comments, maps them to MDX source lines via grep, and generates an LLM-ready prompt string.

---

## Core Workflow

| Step  | Action                                                              | UI                             |
| ----- | ------------------------------------------------------------------- | ------------------------------ |
| **1** | Toggle **Comment Mode** via floating toolbar button                 | Icon button with active state  |
| **2** | **Select text** or **hover-click an element** (heading, playground) | Highlight ring + cursor change |
| **3** | Comment box appears anchored to the selection                       | Popover with textarea          |
| **4** | User types feedback, submits                                        | Comment saved to state         |
| **5** | `grep` finds the relevant MDX source line                           | Beep boop                      |
| **6** | **Generated prompt** is copied to clipboard                         | Dialog with code block         |

## How Grep Maps Comments to MDX Lines

The editor already has access to the raw MDX source (loaded by the Vite plugin). When a user selects text or clicks an element, the system:

1. **Records the anchor** — either the selected text string, or the element&rsquo;s heading text / <span className="rounded bg-muted px-1 py-0.5 text-xs font-mono">&lt;Playground&gt;</span> index
2. **Searches the source** — runs <span className="rounded bg-muted px-1 py-0.5 text-xs font-mono">grep -n</span> against `.plannar/plans/*.mdx` to find the line number
3. **Resolves dups** — if multiple files match, the current file takes priority
4. **Generates output** — formats as `line N file: "quoted context" — comment text`

## Component Tree

Here&rsquo;s the React component architecture for the feature:

| Component         | Responsibility                                                                           |
| ----------------- | ---------------------------------------------------------------------------------------- |
| `CommentProvider` | Context provider — holds comment mode state, collected comments, manages add/edit/delete |
| `CommentToggle`   | Floating toggle button with `MessageSquarePlus` icon                                     |
| `CommentOverlay`  | Wraps plan content — intercepts selections and hover-clicks when mode is on              |
| `CommentBox`      | Popover with textarea, quote preview, and submit button                                  |
| `CommentList`     | Sidebar/panel showing all collected comments                                             |
| `CommentItem`     | Single comment card with context, text, line ref, edit/delete                            |
| `PromptDialog`    | Dialog showing the generated LLM prompt with copy button                                 |

## Implementation Steps

### Phase 1 — State & Toggle

1. **`useCommentState` hook** — `{ mode, comments: Comment[], toggle, addComment, removeComment, editComment }`
2. **`CommentToggle` component** — floating button in bottom-right, animated icon on mode toggle
3. Wire into `App` or `PlanView` via context

### Phase 2 — Text Selection

1. **`CommentOverlay`** wraps plan content with `onMouseUp` listener
2. On `mouseup` in comment mode, read `window.getSelection()`
3. If text selected, show `CommentBox` positioned near selection
4. On submit, store comment with selected text + file + scroll position

### Phase 3 — Element Highlighting

1. When comment mode is on, use `onMouseOver` to highlight interactive elements
2. `data-commentable` attribute marks headings, playgrounds, code blocks
3. Clicking an element opens `CommentBox` anchored to that element
4. Store comment with element type + heading text / playground index

### Phase 4 — Grep & Prompt Generation

1. Add `grepLineNumber(anchor: CommentAnchor): Promise<number>` utility
2. Uses `child_process.execSync` with `grep -n` against the plans directory
3. Falls back gracefully if grep fails (show warning, comment without line number)
4. `generatePrompt(comments: Comment[]): string` — formats the final output

### Phase 5 — Polish

1. Animations for comment box open/close
2. Keyboard shortcut (`Esc` to exit comment mode, `Enter` to submit)
3. Toast notification when prompt is copied
4. HMR-safe — comments survive hot reload (optionally)

## Edge Cases

- **No text selected** — comment anchors to the nearest parent element (heading, playground)
- **Duplicate matches in grep** — prefer exact match, fall back to first match in current file
- **File not found** — show warning, store comment without line reference
- **Comment mode + Playground interaction** — comment mode disables playground bindings (or they coexist with separate click targets)
- **Long selections** — truncate quoted context in sidebar to ~80 chars
- **Empty comment** — prevent submission, show validation
